# Design system

The shared rules (direction, color roles, type, the `console-*` grammar, the reticle, the full response viewer, hero, docs chrome, page edges, density, motion, checks) live in the one agntn design system document, kept with the agntn skills until it ships in the shared package. This file records only what puzzles owns and where it departs from the shared rules. It does not repeat them.

## Anatomy

- **Lock instrument.** Bar `Call await get("<id>")`, the sample's number on the walk, chain and address kind; the cursor loops while the module loads. The subject band puts a dial where a dossier puts its reticle: one position per collection in manifest order, the ring each collection's bounty (closed share hatched, open share in the accent, active position in full accent), notches with a longer one every six; the wedge turns the short way in 700 ms with a slight overshoot. The hub holds the lock glyph, the state word (`locked` in the accent, an open lock for `solved`, `claimed`, `swept`, a timer for `expired`) and the key. Beside it the `Puzzle / <key>` label, the id at 28 px, one sentence and four readouts: prize, key (search range or published material), address, verify. A time band `On chain [ first year to last year ]` from `FACTS_STATIC` draws the record's span, hatched from a hollow start node to a filled solve node, or to the axis end in the accent while unsolved. The dial stays sparse: rotated labels, graduations, rim circuits and faint spans of other samples all read as clutter. Below 72rem the dial column narrows to 14rem and the readouts go two by two.
- **Tool console.** Bar `puzzles_show("b1000/71")`; hosts that don't fit the bar go to the footer (`MCP · Pi · OMP / no network`). Readout: prize (accent while open), address, public key, one `On chain` row with transaction count and start date. Merging two rows and moving the arguments to the bar took it from 543 to 438 px.
- **Verification console.** Shield glyph on the reticle; one readout of three calls, each the call, its value with a square marker (accent filled for a value, hollow for nothing, red for a mismatch) and one sentence. Values stay one line (`{ verified: true }`, `{ verified: false, unavailable }`, `{ verified: false, error }`); the derived address or error goes in the sentence. Rows are grids, and below 30rem every value moves under its call at once.
- **Author card.** The author's key and file number in the bar; readout of collections as links, puzzles with the open count in the accent, years active and a tick gauge, all from the static facts.
- **Record file.** A `File`, not a dossier: no reticle or readout. Bar with `src/collections/<key>/<name>.ts` and the field count; `Record [ as written ]` with copy over a numbered `console-snippet`. Long values shortened on screen, copied whole; values roll with the sample, the comma with them. One height for all samples through `.record-sizer` over `LANDING_STATIC` in one `minmax(0, 1fr)` column: 426 px at desktop, 414 px on a phone. Below 400 px the gutter narrows so `hashCollisionPuzzleSha1` fits at 320 px.
- **Custom collection.** Static, nothing walks. `mine.ts` with the class, static key and exported instance, the record from `./mine/first`; `main.ts [ loads on first get() ]` with `registerCollection({ key, load })` over several lines. Each file has its own copy button.
- **Registry map.** Bar `Call get("<id>")`, meta `manifest`; the cursor loops only while the sample's collection is not in `loaded`. `Manifest [ one import() per key ]`: one cell per key (`minmax(9.5rem, 1fr)`, `8rem` below 400 px) with icon, key and a 5 px node, hollow for a key only, accent outline once loaded, filled for the shown collection; every cell links, carries a `UTooltip` and an accessible state. A gauge replaces the paragraph: one tick per key, `loaded 13 / 24 · 11 still keys`. Footer `import() loads no records · one chunk per key` and the collection link. The set of loaded keys is the page's own record of the walk, not a claim about the library's cache.
- **Start.** Bar `Start` with the install command and `Node.js 24 or newer`; notes `Pin`, `Data`, `Balance`; `First lookup [ index.ts ]` from `LANDING_STATIC`, so the fixture test pins its values.
- **Collection dossier.** ID bar with the key, `16 / 20` in manifest order, the puzzle count and start date range. Subject: collection icon, `Collection` label, title, key and chains, blurb; readout author, prize recorded, still unsolved in the accent (`none` plain), one tick per puzzle. Census: a counter per status in record order, then public and private keys after a brighter divider, each a 10 px label, an 18 px number with a dimmed percent and a 2 px bar (unsolved in the accent). Access leads `getCollection("<key>")` and the playground. Hints only when the collection has shared ones, `Source` and `Confirm` on one row per hint. Footer: author, all collections, locality, data version.
- **Puzzle page and dossier.** The hero id is mono, collection key dimmed and name bright, broken only after the slash. The sentence leaves the address to the dossier. ID bar with `66 / 256` (none for a singleton), start and `→` solve date. Subject: chain glyph, `Puzzle / <collection title>`, chain, address kind, `StatusPill`, a `pre-genesis` flag, then the record as written. Readout prize, key material, verification, solved; one tick per transaction, money out in the accent. Bands: trail (explorer, source, solver, playground leads beside the address node and live balance; stacked below 900 px), key (only when the record carries one), transactions (eight rows, then a button; txid under the row below 640 px), files and hints (collection hints first with a `collection` tag). Responses `03 Full tool response` and `04 Serialized record`. Footer: previous, next, collection, and `local record / balance from the explorer`.
- **Puzzle list.** Bar `List <key>.all()` with one 2 px tick per puzzle and status counts. A named collection, or a numbered one under 20 puzzles, gets `console-rows` (name, `StatusPill`, prize, leader, address, key glyphs); a numbered one of 20 or more a grid of square cells from 2.5rem, a closed cell on a 3 px hatched strip (red for `swept`), an open one with a half accent edge, a 3 px corner square for a published private key.
- **Rosters.** Authors end in their collection keys and puzzle count, solvers in the identifiers of their solves, collections in `77 of 256 open` (or `open`, `closed` for a single puzzle) with chain glyphs beside the key. The solver dossier reads `Solves`, `Prize recorded` and `Also author` in the accent when the key published a collection, with a `Solves` band of rows.
- **Landing roster.** Read off `FACTS_STATIC` so it renders before any collection loads; keeps the manifest order, adds an unclaimed column (`none` dimmed), marks the walk's row with an accent edge on its first cell and `--puzzles-cell-active`. Every cell one line with the rest in a tooltip; cells `align-middle`, because a clipped name rode above the baseline.
- **Playground.** Two instruments stacked at full width; a 2/5 column squeezed them. Request: `CALL`, the tool and its number among eight, operations as leads with the chosen description from `facts`, inputs as readout rows, sample chips, then the CLI line and the MCP JSON under rule titles with copy, the permalink in the footer (`every state is a link`). Response: operation tag, the call, a truthful meta; `show`, `verify`, `balance`, `author`, `stats` fill the subject band, `list`, `collections`, `authors` print rows, an error fills the subject alone; footer with the measured milliseconds. Circuits `call` and `answer` (`.playground-link`); the response cursor loops only while a call is in flight. The verification note is a zone line with a `Note` tag. Tokens sit in a `<code>`, since `.console-snippet > span` would win over `tok-*`. Below 80rem the operations fall into one column, below 56rem the bands stack.
- **Changelog.** Hero readouts: releases, latest with its date in the accent, entries with the breaking count; a `RSS` zone line; circuit `log`. `ChangelogFeed` on `UChangelogVersions`: bar `Log CHANGELOG.md` with one tick per release (accent when breaking), the rail in `--console-line` with its scroll beam, square nodes, the latest in the accent, the date left of the rail from lg with the npm publish time under it; version in mono 18 px as the anchor, `Latest` and `N breaking` tags; groups under rule titles, entries in Figtree 14 px with scope and `Breaking` tags; release foot with `↗ release`, `↗ compare` and contributors. The page and `/changelog.xml` read the prerendered `/api/changelog`.
- **Chrome parts.** Logo: the lock from the lock instrument. Areas: `Docs` (lit on the guide, collections, authors, solvers), `Playground`, `Changelog`. Sidebar index rows are the collections, authors and solvers overviews and the guide's first page. A group page count was dropped: it counted the overview and disagreed with the collection count.

## Motion

| Change                    | Motion                                                                                                                        |
| ------------------------- | ----------------------------------------------------------------------------------------------------------------------------- |
| new sample on the landing | lock wedge 700 ms with overshoot, hub lock arcs, circuit accent down the rail, record file path and values roll               |
| collection module loading | lock and registry cursors loop (`console-cursor-busy`)                                                                        |
| collection page load      | census bars grow from the left once                                                                                           |
| playground load, answer   | operation leaders draw 60 ms apart once; readout and list rows 45 and 30 ms apart per answer; response cursor loops in flight |
| reduced motion            | no walk timer, no roll, no wedge turn; manual steps work                                                                      |

## Differences

- **OG fonts:** puzzles relies on `@nuxt/fonts` alone, so Takumi falls back to Inter. Waits on the family's open decision.
- **Lock instrument:** a dial in place of the reticle, because the lock is the domain (a prize behind a key) and replaced a diagram of the manifest.
- **Record file and custom collection:** no subject band or readout; they are files and the dossiers already carry the record.
- **Custom collection lines** wrap between words (`overflow-wrap: break-word`) instead of ending in an ellipsis: the example is static, so there is no walk whose height must hold, and a string such as `"./mine"` must never split at its slash.
- **Landing roster** keeps manifest order instead of largest first.
- **Class prefix** `puzzles-` for the site's own classes, `.dossier-*` for the entity dossiers' shared parts at the end of `app.css`.
