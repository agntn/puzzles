## Run it

```bash
pnpm add -g @agntn/puzzles
puzzles stats
```

::dataset-stats
::

| Command                     | Description                                                                                                                                                          |
| --------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `puzzles stats`             | Totals and status counts across every collection. `--json` adds the prize sums                                                                                       |
| `puzzles collections`       | One line per collection: key, count, the count per status, author                                                                                                    |
| `puzzles authors [key]`     | One line per author, or one author's record by author key or collection key: aliases, profiles, addresses, sourced facts                                             |
| `puzzles solvers [key]`     | One line per named solver, or one solver's record by solver key or puzzle identifier: every solve with date and prize, profiles, sourced facts                       |
| `puzzles show <id>`         | One puzzle: id, status, prize, address. `--json` for the whole record                                                                                                |
| `puzzles hints <id>`        | The collection's hints first, then the puzzle's own, then its hint files. `--json` for both                                                                          |
| `puzzles stages <id>`       | The stages of a puzzle that runs in several: what each shows, its pages and files, and the published answer when there is one. `--json` for the list                 |
| `puzzles list [collection]` | Puzzles, one per line, `--address`, `--chain`, `--status <status>` and `--with-pubkey` to narrow, `--limit <n>` and `--offset <n>` to page, `--json` for the records |
| `puzzles verify [id]`       | A published key against its address, or `--all` for every puzzle, `--quiet` for the exit code alone                                                                  |
| `puzzles balance <id>`      | The live balance through the chain's explorer, `--api-key` for Ethereum                                                                                              |
| `puzzles export`            | The complete dataset envelope, `--compact` without indentation                                                                                                       |
| `puzzles mcp`               | Run the MCP server over stdio                                                                                                                                        |

## Examples

```bash
puzzles list b1000 --status unsolved              # one line per unsolved puzzle: id, status, prize, address
puzzles list --with-pubkey --json | jq -r '.[].id' # every puzzle with a known public key
puzzles list --chain ethereum                      # every Ethereum record, wherever it lives
puzzles list --address 1BgGZ9tcN4rm9KBzDn7KprQz87SZ26SAMH # which puzzle is this? b1000/1
puzzles list b1000 --limit 5 --offset 70           # five rows from b1000/71, not the whole collection
puzzles show hash_collision/sha256 --json          # the record, redeem script included
puzzles hints b1000/71                             # the author's one statement about the keys
puzzles verify b1000/135                           # OK	b1000/135
puzzles solvers b1000/135                          # the solver behind it: RetiredCoder, four solves
puzzles export --compact > puzzles.json            # a snapshot with its data_version
puzzles stats --json | jq -c .unsolved_prize       # {"AR":…,"ETH":…,"BTC":…}, what is still on the table
```

A `collections` row prints the key, the puzzle count, the statuses and the author, `b1000: N puzzles, N solved, N unsolved, N swept, by saatoshi_rising`: solved and unsolved always, then claimed, swept and expired when the collection has any, so the counts add up to the total. The line format of `show` and `list` is tab separated: `b1000/71	unsolved	7.100226 BTC	1PWo3JeB9jrGwfHDNpdGK54CRas7fsVzXU`. A puzzle without a recorded prize prints `-` in the third column. Statuses for `--status` are `unsolved`, `solved`, `claimed`, `swept` and `expired`. Anything else is an error, not an empty list. `--limit` and `--offset` page the rows the way `puzzles_list` pages them for a model: the offset skips matching puzzles after the filters, in dataset order. There is no default limit, a bare `list` still prints every match. Both want an integer, `--limit 0` or `--offset -1` is an error. `--address` goes the other way: you have an address and want the record behind it. Case matters only where the chain says it does, so an EIP-55 Ethereum address and a shouted bech32 one both find their puzzle, while a recased base58 string does not, because that is a different address.

## Exit codes

`show`, `hints`, `stages`, `verify`, `balance` and a `list` with an unknown collection print a message and exit 1. `verify --all` exits 1 when any puzzle with a key derives the wrong address. Puzzles without a key don't count, which is what a CI gate wants. `list` with a status that matches nothing prints nothing and exits 0. Don't use an empty list as a check.

```bash
puzzles verify --all --quiet && echo "every published key derives its address"
```

A closed pipe ends the process quietly: `puzzles export | head` doesn't crash with an EPIPE trace. And `--help` loads neither the MCP SDK nor the verification crypto. citty resolves every subcommand to print the usage, so `mcp` imports the server and `verify` imports `@agntn/keys` when they run, and listing the commands loads no collection and no curve.

## Machine output

`--json` goes through one serializer. It prints `bigint` as a string and leaves absent fields out. Nothing on the CLI prints data through a logger. consola silences its output under `NODE_ENV=test`, and a script that parses an empty string fails far from the cause.
