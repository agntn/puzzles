## By identifier

```ts
import { get, requirePuzzle } from "@agntn/puzzles";

await get("b1000/71"); // the puzzle, loading b1000 only
await get("gsmg"); // a singleton, the key is the id
await get("b1000/999"); // undefined
await requirePuzzle("b1000/999"); // throws PuzzleNotFoundError
```

`get` reads the collection key off the identifier, loads that collection, and asks it. A bad collection segment loads nothing, and a non-string value from untyped JavaScript is a miss instead of a `TypeError`. `peter_todd/sha1` works, because the alias resolves before the load.

## Inside a collection

```ts
import { b1000 } from "@agntn/puzzles/collections/b1000";
import { zden } from "@agntn/puzzles/collections/zden";

b1000.get(71); // NumericCollection takes numbers, or "71", or "b1000/71"
b1000.get("0x47"); // undefined, the spelling has to be the identifier's own
b1000.require(71); // throws when missing
zden.get("decred_janus"); // NamedCollection takes the name, or the full id
zden.requireId("zden/decred_janus"); // the full id on any collection

b1000.all(); // every puzzle, in list order
b1000.solved(); // status === "solved"
b1000.unsolved(); // status === "unsolved"
b1000.withPubkey(); // a public key is known
b1000.count(); // 256
b1000.solvedCount(); // 83
b1000.unsolvedCount(); // 77
```

Pick `get` when a miss is normal. Pick `require` when a miss is a bug. A query resolves only in the spelling its identifier uses: `" 71 "`, `"71.0"` and `"7e1"` are misses on `b1000`, whatever `Number()` makes of them, and a `NamedCollection` handed anything but a string answers `undefined` rather than throwing. `all()` is a frozen array built once. `solved()`, `unsolved()` and `withPubkey()` filter it on every call, so keep the result if you loop.

## Across collections

```ts
import { all, Chain, selectPuzzles, Status } from "@agntn/puzzles";

await all(); // 348 puzzles in manifest order, then list order
await selectPuzzles({ collection: "b1000", status: Status.Unsolved }); // 77
await selectPuzzles({ status: Status.Solved, withPubkey: true }); // every solved puzzle with a known public key
await selectPuzzles({ chain: Chain.Ethereum }); // 7, four of them in the collection called arweave
await selectPuzzles({ address: "1BgGZ9tcN4rm9KBzDn7KprQz87SZ26SAMH" }); // b1000/1
```

`selectPuzzles` with a collection loads that collection alone. Without one it loads everything. `withPubkey: true` keeps the puzzles whose public key is known. That's what a scanner wants: a public key turns a hash search into a discrete log search. `address` answers the question an identifier cannot: you saw an address somewhere and want to know whether the dataset already knows it. It compares on each record's own chain, through `sameAddress`, so an EIP-55 checksummed Ethereum address and an uppercased bech32 one both match. Base58 does not fold, because a recased base58 string is a different address. `chain` is the filter an identifier cannot stand in for. 330 of the 348 puzzles are on Bitcoin, and a collection key names its author or its puzzle, not its chain: four of the seven Ethereum records live in the collection called `arweave`.

## Statistics

```ts
import { collectionSummaries, stats } from "@agntn/puzzles";

await stats();
// {
//   total: 348, solved: 142, unsolved: 96, claimed: 11, swept: 96, expired: 3,
//   with_pubkey: 247,
//   total_prize: { AR: 5550, ETH: 22.74624155, DAI: 100, BTC: 1064.10258961, LTC: 230.8255, DCR: 460 },
//   unsolved_prize: { AR: 1900, ETH: 9.61254155, BTC: 908.88130493 },
// }

await collectionSummaries(); // [{ key, author, total, claimed, expired, solved, swept, unsolved }, ...]
```

Prizes are summed per currency in whole units, the way the records write them, rounded to eight places. Nothing here is a balance. A `swept` puzzle's prize is what sat on the address when it was swept. An `expired` one's went back to the author.

## The dataset snapshot

```ts
import { dataset, datasetCollections, dataVersion } from "@agntn/puzzles";

await dataVersion(); // "f12fce3179b5", the first 12 hex characters of SHA-256 over the serialized collections
await datasetCollections(); // [{ name, author, puzzles: [PuzzleData, ...] }, ...]
await dataset(); // { version, data_version, collections }
```

`dataVersion()` changes when a record changes and stays the same across runtimes. Cache a snapshot, compare it later, no build step. No timestamp in it, no environment data. The snapshot comes back frozen through, envelope, rows and records included, so decorating a serialized record is a `TypeError` in strict mode rather than a rewrite of the export for every other reader. `puzzles export` prints `dataset()`. That's what the JSON consumers of the old dataset read now.

## Explorer links

```ts
const puzzle = await requirePuzzle("zden/decred_janus");

puzzle.explorerUrl(); // "https://dcrdata.decred.org/address/DsRaAja82UvgnqYaBHYFuyCKURFX2rCyEJ8"
puzzle.claimExplorerUrl(); // the claim transaction, when there's one
```

Explorer bases come from `@agntn/chains`: blockstream.info for Bitcoin, litecoinspace.org for Litecoin, etherscan.io, dcrdata.decred.org and viewblock.io for Arweave. Need a link for something that isn't a puzzle? `addressExplorerUrl(chain, address)` and `transactionExplorerUrl(chain, txid)` are exported too.
